# iframe Embedding Specification (`/embed` + npm `@firetable/project-xiaochun`)

> Embed Project XiaoChun into third-party web pages via `<iframe>`: hosts require only a single `<script>` line or `npm i @firetable/project-xiaochun`, with the SDK managing lazy loading, handshakes, origin verification, transparent click-through, and teardown.  
> Main site behavior remains unchanged; `/embed` provides a **lightweight entry point** (omitting TopHeader / DevDrawer / update modal / LoadingOverlay) and **does not pre-warm WebLLM or EMAGE by default**.

**Core Files**
- [`src/routes/embed.tsx`](../src/routes/embed.tsx) · [`src/embed/EmbedApp.tsx`](../src/embed/EmbedApp.tsx) · [`src/embed/bridge.ts`](../src/embed/bridge.ts) · [`src/embed/params.ts`](../src/embed/params.ts)
- [`src/lib/securityHeaders.ts`](../src/lib/securityHeaders.ts) (Response headers policy) · [`src/lib/heavyPreload.ts`](../src/lib/heavyPreload.ts) (Heavy resource lazy-loading toggle)
- [`public/_headers`](../public/_headers) · [`wrangler.jsonc`](../wrangler.jsonc) (`EMBED_FRAME_ANCESTORS`)
- [`packages/project-xiaochun/`](../packages/project-xiaochun/): SDK, `<xiaochun-avatar>`, protocol constants (`src/protocol.ts`, **shared** between `/embed` and SDK)
- [`.github/workflows/publish-npm.yml`](../.github/workflows/publish-npm.yml) · `scripts/bump-version.mjs` (Synchronizes npm package versions)

## 1. Architecture

```mermaid
sequenceDiagram
    autonumber
    participant Host as Host Page (SDK)
    participant Frame as iframe /embed (bridge.ts)
    Note over Host: lazy: render fixed-dimension placeholder (zero CLS)<br/>Mount iframe only when visible + idle / clicked / API invoked
    Host->>Frame: Mount iframe /embed?host=<Host Origin>&transparent=1…
    Frame-->>Host: xc.ready (window.postMessage, targetOrigin = Host Origin, includes capabilities/version)
    Note over Host: Verify event.source === iframe.contentWindow && event.origin ∈ allowedOrigins
    Host->>Frame: xc.init (window.postMessage, targetOrigin = iframe origin, transfers MessagePort)
    Note over Frame: Verify event.source === window.parent && event.origin ∈ Host Whitelist; accepts only one init
    Frame-->>Host: (All subsequent traffic uses MessagePort) xc.state / xc.load.progress / xc.loaded
    Host->>Frame: xc.say / xc.motion / xc.expression / …
    Frame-->>Host: xc.utterance / xc.stt / xc.hit-region / xc.error
```

- **One iframe = One complete engine instance** (isolated WebGL context, dedicated Web Worker, isolated IndexedDB partition); see §7 Risks.
- Post-handshake communication **exclusively** uses `MessageChannel`; the port itself acts as the capability token, removing dependence on `window.postMessage(..., '*')`.
- Automatic rendering suspension when invisible:
  1. In-iframe `visibilitychange` (engine's built-in `bindVisibilityPause`);
  2. SDK uses `IntersectionObserver` to dispatch `xc.pause` when outside viewport, and `xc.resume` upon return;
  3. Explicit host `pause()` takes highest precedence (`vrmEngine.hostPaused`, foreground visibility will not resume rendering).

### `/embed` URL Parameters (Auto-generated by SDK; manually constructed if hand-crafting `<iframe>`)

| Parameter | Default | Description |
| :-- | :-- | :-- |
| `host` | — (**Required**) | Host page origin. If missing and impossible to infer from `ancestorOrigins`/`referrer`, handshake **fails closed** (does not emit `xc.ready`, rejects `xc.init`). |
| `allow` | — | Additional allowed host origins for handshakes (comma-separated); **`*` is rejected**. |
| `transparent` | `0` | `1` = Transparent background overlaid atop host page. Only `/embed` and Tauri allow transparent scenes; standard browser tabs remain restricted. |
| `ui` | empty (all hidden) | Built-in UI widgets to display, comma-separated: `chat` (Chat bar) · `bubble` (Head speech bubble) · `outfit` (Wardrobe switcher button) · `scene` (Scene switcher button) · `lang` (Language switcher) · `github` (GitHub repository link). Example: `?ui=chat,outfit,scene,lang,github`. Whitelist validated; unknown items ignored with `console.warn`. See §2.7. |
| `uiAutoHide` | `transparent` | Built-in UI display strategy, **identical to Tauri desktop pet**: `transparent` (default) = initially hidden in **transparent scene**, click character to toggle, always visible in light/dark scenes; `1`/`true` = click-to-show across all scenes; `0`/`false` = always visible. Invalid values ignored. See §2.7. |
| `cameraFov` / `cameraDistance` / `cameraHeight` / `cameraIntro` | do not override | Camera: field of view 15–60° · distance 1–15m · framing height offset ±1m · play cinematic intro (`0`/`1`). Out-of-bounds values clamped; invalid values ignored with `console.warn`. See §2.9. |
| `lang` | iframe stored → browser lang → `zh-CN` | `zh-CN` · `en` · `ja`. Priority: URL `lang` (SDK `lang` option) > iframe localStorage last chosen by user via button (`xiaochun_embed_lang`) > `navigator.languages` (`zh*`→`zh-CN`, `ja*`→`ja`, `en*`→`en`) > `zh-CN`. **Does not touch main site language cookies**. |
| `heavy` | `lazy` | `lazy` = Do not pre-warm WebLLM / EMAGE; `eager` = Same as main site, pre-warm immediately after VRM load. |
| `outfit` | default addon | Initial outfit ID. **Strictly validated**: must match `^[a-z][a-z0-9_]{0,63}$` and exist in built-in list (`Object.hasOwn`); falls back to default on error, emitting `xc.error{unknown_id, command:'outfit'}` post-handshake. |
| `scene` | follows `transparent` / `theme` | Initial scene: `light` / `dark` / `transparent` / `beach3d`. Strictly validated; priority: `scene` > `transparent=1` > `theme` > system light/dark. Explicit assignment prevents system theme changes from switching scenes. |
| `theme` | follows system | Linework theme (`light` / `dark`) when non-transparent. |
| `controls` | `1` (enabled) | Scroll wheel zoom, matching main site. `0` = Force disabled; `1` = Enabled. In **transparent scenes**, only zooms when pointer is over character pixels, passing wheel events to host otherwise. In **opaque scenes**, entire iframe area captures wheel events as zoom, **suppressing host page scrolling in that box** (use `controls=0` if host scrolling is needed). |

## 2. postMessage Protocol (v1)

Messages use the `xc.` prefix and envelope: `{ type, v: 1, id?, payload }`. Types and constants are defined in [`protocol.ts`](../packages/project-xiaochun/src/protocol.ts).  
Host commands may attach an `id`; matching `xc.error` / `xc.utterance` events echo this `id` (allowing SDK `say()` to resolve on `end`).

### 2.1 Host → iframe

| Message | Payload | Status | Maps to |
| :-- | :-- | :-- | :-- |
| `xc.init` | `{ hostOrigin }` + transfers `MessagePort` | ✅ | Handshake completion (once only). |
| `xc.say` | `{ text, mode?: 'speak' | 'chat' }` | ✅ | `speak` → protocol action `speak` (same handler as `xiaochun://speak?text=`) → `vrmEngine.speakText` (TTS + EMAGE, **bypasses LLM**); `chat` → `vrmEngine.sendMessage` (via WebLLM / custom provider, loads LLM weights). Max length `MAX_SAY_CHARS=2000`. |
| `xc.audio` | `{ source: ArrayBuffer | Blob | url, mimeType?, format?, sampleRate?, channels?, text?, motion?, lipsync?, audible? }` | ✅ | Host supplies **complete audio segment without TTS**: in-iframe decoding → mono → 16 kHz → EMAGE window inference (motion) + synchronized playback + RMS lipsync. `audible: false` keeps motion and lip-sync but sets playback gain to 0. See §2.4. Envelope `id` correlated with `xc.utterance` / `xc.error`. |
| `xc.audio.chunk` | `{ data: ArrayBuffer, format: 'pcm16' | 'float32', sampleRate, channels?, text?, motion?, lipsync?, audible? }` (Envelope `id` = stream ID) | ✅ | Streamed PCM chunking; first chunk with a given `id` initializes the utterance, subsequent chunks append. Options, including `audible`, take effect on the first chunk. |
| `xc.audio.end` | `{ abort?: boolean }` (Envelope `id` = stream ID / `xc.audio` ID) | ✅ | Finalizes playback (finishing received buffer); `abort: true` halts immediately. Full `xc.audio` invocations can be aborted via this `id` (SDK `AbortSignal`). |
| `xc.motion` | `{ url | name, loop?, fadeDuration?, timeScale?, mask? }` or `{ stop: true }` | ✅ | `vrmEngine.playMotion` / `stopMotion`. Limited to HTTPS or same-origin `.vrma`; built-in name currently only `thinking`. |
| `xc.expression` | `{ name }` (`neutral/happy/angry/sad/relaxed/surprised`) | ✅ | `vrmEngine.setExpression`. |
| `xc.pointer` | `{ x, y }` (iframe client coordinates) | ✅ | `vrmEngine.isHitModel` → replies with `xc.hit-region` (**hit-testing only; does not drive gaze**). |
| `xc.setOutfit` | `{ id }` | ✅ (`outfits` capability) | Switch wardrobe outfit. `id` must match `^[a-z][a-z0-9_]{0,63}$` and exist in `capabilities.outfits` (`base` is private). **Serialized + last-wins**, see §2.6. Resolves with `xc.outfit-changed`. |
| `xc.setScene` | `{ id }` | ✅ (`scenes` capability) | Switch scene (`light` / `dark` / `transparent` / `beach3d`). Immediate effect, emits `xc.scene-changed`. |
| `xc.prefetch` | `{ ids?: string[] }` | ✅ (`prefetch` capability) | Downloads outfit assets directly into IndexedDB without unpacking. Omitting `ids` downloads all built-in outfits **except wedding dress** (13.9MB, requires explicit ID). Serialized, scheduled after EMAGE, respects Data Saver (`saveData`). Resolves with `xc.prefetched`. |
| `xc.setModel` | `{ outfit }` or `{ url, name? }` | ✅ (Legacy compatibility) | Legacy command. `outfit` routes to same pipeline as `xc.setOutfit` (rejects `base`); `url` (HTTPS / same-origin `.vrm`, requires CORS) is **disabled by default**, requiring `allowCustomModel: true` in config. |
| `xc.setConfig` | `{ lang?, transparent?, ui?, uiAutoHide?, camera?, heavy?, allowCustomModel?, gestures? }` | ✅ | Dynamic updates for i18n, internal scene switches, UI widget visibility, UI display mode, camera overrides, and heavy pre-warming. |
| `xc.mic` | `{ enabled }` | ✅ | `SttClient.start/stop` (SenseVoice, downloads model on first invocation), results dispatched via `xc.stt`. |
| `xc.pause` / `xc.resume` | — | ✅ | `suspendRendering` / `resumeRendering`. |
| `xc.destroy` | — | ✅ | `releaseHeavyResources` + `vrmEngine.dispose` + port closure; SDK unmounts iframe. |
| `xc.lookAt` | `{ x, y }` | ⏳ **unsupported** | Returns `xc.error{code: 'unsupported'}`. |

### 2.2 iframe → Host

| Message | Payload | Description |
| :-- | :-- | :-- |
| `xc.ready` | `{ version, protocol, capabilities: { commands[], unsupported[], stt, transparent, audio?, crossOriginIsolated?, outfits?, scenes?, prefetch?, gestures?, camera? } }` | Initial handshake step (`window.postMessage`, strict `targetOrigin`). Retries every 1s (up to 10 times) until `xc.init` received. |
| `xc.load.progress` | `{ phase: 'model' | 'outfit' | 'prefetch', progress: 0-100, id? }` | Progress streaming for model initialization, wardrobe loading, or prefetching. Emitted on integer percentage steps. |
| `xc.loaded` | `{ model }` | Initial model or `setModel` completed (resolves SDK `ready` Promise). |
| `xc.outfit-changed` | `{ id | null, name, previous?, initial?, noop? }` | Outfit active. Emitted with `initial: true` post-handshake; `noop: true` if already active; custom URLs report `id: null`. |
| `xc.scene-changed` | `{ id, transparent, previous?, initial?, noop? }` | Scene active. Emitted with `initial: true` post-handshake. |
| `xc.lang-changed` | `{ lang, previous?, initial? }` | UI language active. Emitted post-handshake (`initial: true`) and upon user button click or `setConfig{ lang }`. |
| `xc.prefetched` | `{ downloaded[], cached[], failed[], skipped?: 'save-data' }` | Response to `xc.prefetch`. |
| `xc.state` | `{ phase, paused, heavy }` | Current state phase: `loading | idle | thinking | speaking | listening | paused`. |
| `xc.stt` | `{ kind: 'state' | 'progress' | 'text', … }` | Speech-to-text status, download percentage, and transcription text. |
| `xc.utterance` | `{ phase: 'start' | 'end', text, kind?: 'text' | 'audio' }` | Speech lifecycle markers. `kind: 'audio'` indicates host-provided audio. For audio, `start` is sent when the first buffer's clock starts (after the thinking pose and the first EMAGE window), not when the command is accepted. Text `start` is still sent as speech begins. |
| `xc.hit-region` | `{ hit, x, y }` | Pointer intersection state against character; SDK uses this to toggle iframe `pointer-events`. |
| `xc.gesture-move` | `{ gesture, seq, phase: 'start' | 'move' | 'end', dx, dy, totalDx, totalDy, reason? }` | **Only when `gestures.move` enabled**: Dragging character translates iframe. See §2.8. |
| `xc.gesture-resize` | Same as above + `corner: 'NW' | 'NE' | 'SW' | 'SE'` | **Only when `gestures.resize` enabled**: Dragging corner handles resizes iframe. See §2.8. |
| `xc.error` | `{ code, message, command? }` | Error details: `unsupported | bad_request | not_ready | origin_denied | failed | busy | unknown_id`. |

### 2.3 Origin Verification Checklist

| Location | Verification Rule |
| :-- | :-- |
| Host SDK receiving `xc.ready` | `event.source === iframe.contentWindow` **and** `event.origin ∈ {origin} ∪ allowedOrigins`; otherwise discarded with `error{origin_denied}`. |
| Host SDK sending `xc.init` | `targetOrigin` = verified `event.origin` (never `'*'`). |
| iframe receiving `xc.init` | `event.source === window.parent` **and** `event.origin ∈ Host Whitelist`; accepts only the **first** init. |
| iframe sending `xc.ready` | `targetOrigin` = host origin. |
| Post-handshake communication | Exclusively through `MessagePort`. |
| URL-based arguments | URLs for `motion` and `setModel` restricted to HTTPS or same-origin with whitelisted extensions. |
| `normalizeOrigin()` | Rejects `*`, `null`, non-HTTP(S) protocols, and strips paths. |

### 2.4 Host Audio (`xc.audio` / `xc.audio.chunk`): Pipeline & Constraints

EMAGE accepts 16 kHz mono Float32 PCM. In the standard pipeline (`text → /api/tts → MP3 streaming decode → 16 kHz PCM`), TTS simply functions as an audio source. Host-provided audio follows the same pipeline by decoding, downmixing, and resampling directly.

```
xc.audio(ArrayBuffer/Blob/URL)                         xc.audio.chunk (PCM16/Float32 …)
        │ decodeAudioData (OfflineAudioContext 48 kHz)           │ Downmix → Float32
        └──────────────┬────────────────────────────────────────┘
                       ▼  HostAudioInput { sampleRate, chunks }            (src/director/hostAudio.ts)
              PcmSlicer: First slice 2s, subsequent 4s                     (HOST_AUDIO.firstSliceSec / sliceSec)
              │  Per slice: StreamResampler16k ─► EmagePlayer.pushAudioChunk ─► worker inference (T=64) ─► motion
              │             Native rate AudioBuffer (queued playback)
              ▼
        ChatDirector.speakAudio  ── Reuses speakText A/V synchronization (buffers motion until AudioBuffer starts)
                                 ── Lipsync = AnalyserNode RMS × 4 → 'aa' expression
                                 ── Clock start → xc.utterance{phase: 'start', kind: 'audio'}
                                 ── Completion → xc.utterance{phase: 'end', kind: 'audio'}
```

- **EMAGE Requirements**: 16 kHz, Mono, Float32; window size `T=64` frames (~2.13s at 30 fps). Non-vocal audio is accepted, though motions are generated in speech style.
- **Lipsync**: RMS amplitude mapping to mouth opening (`aa`), without viseme alignment; can be disabled via `lipsync: false`. The analyser sits before the gain, so lip-sync still sees the waveform when the speakers are muted.
- **Silent motion**: `audible` defaults to `true`. `false` sets the playback gain to 0. The `AudioContext` clock and lip-sync still follow the buffer, so a host page can play the same audio itself without a second copy from the iframe.
- **A/V Sync**: Motion playback is buffered until the audio buffer starts; playhead syncs with `AudioContext` clock. That clock runs even when `audible` is `false`. `xc.utterance{phase:'start', kind:'audio'}` is emitted at that same `AudioBufferSourceNode.start`, so a host player can stay paused until then and avoid leading the lips.
- **Latency (TTFA)**: Decoding + first 2s slice inference + decode. Benchmarked on desktop Mac CPU (INT8 WASM): warm state TTFA ≈ 0.7s; cold start with models cached ≈ 4.0s. First run requiring model download (71.59 MB total) takes longer; call `xc.setConfig{heavy: 'eager'}` to pre-warm.
- **Streaming**: Supported via `xc.audio.chunk`. Incoming streams are resliced into 2s / 4s segments; segments transition via `onended`.
- **Input Constraints**: Single utterance duration ≤ 120s; encoded payload ≤ 32 MB; sample rates 8000–96000 Hz; PCM little-endian.
- **Zero-Copy**: SDK transfers `ArrayBuffer` objects by default (detaching source buffer unless `{ transfer: false }` is passed).
- **Interruption**: Subsequent `say` or `audio` calls preempt active utterances, dispatching an `end` event to the previous one. `AbortSignal` halts immediately.

### 2.5 Relationship with `xiaochun://` Protocol

`xiaochun://` is an OS-level deep-link protocol dispatched only by native shells. The `/embed` iframe does not and cannot listen to `xiaochun://`. Both interfaces map to the same internal action handlers in `src/core/protocol/`:

| `xc.*` (iframe / Web) | Protocol Action | `xiaochun://` (Tauri Desktop) |
| :-- | :-- | :-- |
| `xc.say{text}` (`mode: 'speak'`) | `speak { text }` | `xiaochun://speak?text=…` |
| `xc.say{mode: 'chat'}` | — (WebLLM pipeline, no deep-link equivalent) | — |
| `xc.audio{source: URL}` | `speak { audioUrl[, text] }` | `xiaochun://speak?audioUrl=…[&text=…]` |
| `xc.audio{source: ArrayBuffer}` / `xc.audio.chunk` | `audio { source | stream }` | — (Binary payloads unsupported in URLs) |
| — | `speak { file }` | `xiaochun://speak?file=…` (Desktop only) |

### 2.6 Outfits, Scenes & Prefetching

- **Version Negotiation**: Capabilities are advertised in `xc.ready.capabilities`. Unsupported calls on legacy iframes reject locally with `[unsupported]`.
- **ID Validation**: Validated against `^[a-z][a-z0-9_]{0,63}$` and checked via `Object.hasOwn()`. Prototypes and `base` reject with `unknown_id`.
- **Concurrency**: Switching outfits is serialized with last-wins semantics. Ongoing downloads complete safely; redundant intermediate requests reject with `[busy]`. Wardrobe switches do not interrupt active speech.
- **Scenes**: 4 built-in scenes (`light`, `dark`, `transparent`, `beach3d`). `beach3d` (display name "Beach") is an opaque, real-time Three.js 3D beach stage (see [`BEACH3D_SCENE.md`](BEACH3D_SCENE.md)); only `transparent` is transparent.
- **Persistence**: User selections via built-in buttons persist in the iframe's partitioned localStorage (`xiaochun_wearing_outfit`, `xiaochun_scene_theme`). Host explicit parameters take precedence over stored preferences without overwriting them.
- **Prefetching**: `xc.prefetch()` caches outfit assets into IndexedDB. The wedding dress (`xiaochun_wedding`, 13.9 MB) is excluded from default bulk downloads and requires explicit selection.

### 2.7 Built-in UI Widgets (`ui`) & Display Strategy (`uiAutoHide`)

The `ui` array controls which widgets are mounted: `chat`, `bubble`, `outfit`, `scene`, `lang`, `github`.

| `uiAutoHide` Mode | Behavior |
| :-- | :-- |
| `'transparent'` (**Default**) | In **transparent scenes**, UI is initially hidden; click character to toggle display; click blank space to hide. In light/dark scenes, UI is always visible. Matches Tauri pet behavior. |
| `true` | UI is hidden initially across all scenes, appearing only on character click. |
| `false` | UI remains permanently visible across all scenes. |

- **Click Detection**: Single-click defined as displacement ≤ 6px (`CLICK_MAX_MOVE_PX`), evaluated across client and screen coordinates to avoid false triggers during window dragging.
- **Hit Discrimination**: Clicks on UI buttons, menus, and text inputs are ignored by the auto-hide detector; clicks on the character toggle UI; clicks on empty space dismiss UI.
- **Auto-Dismiss**: UI auto-hides after 10 seconds of inactivity (`PET_UI_DURATION_MS`), pausing the timer while menus are open or chat is actively composed.

### 2.8 Gestures: Window Movement & Corner Resizing

Enables desktop-pet interactions inside `/embed`: dragging the character moves the iframe; dragging corners resizes it.

| Capability | Reused Engine Core | Description |
| :-- | :-- | :-- |
| Movement | `GestureMachine` with `'delta'` strategy | Uses 10px slop threshold and 480ms long-press arming; dispatches `xc.gesture-move` via `InteractionController`. |
| Resizing | `ResizeGesture('delta')` + `corners.ts` | 40px corner hit zones (`CORNER_HIT_SIZE`), corner cursors (`nwse-resize`, `nesw-resize`), and arc styling identical to Tauri. |

- **Negotiation**: Disabled by default. Enabled when host specifies `draggable` / `resizable` in config.
- **Message Protocol**: `xc.gesture-move` and `xc.gesture-resize` transmit cumulative displacements (`totalDx`, `totalDy`) alongside delta steps, ensuring immunity to dropped frames.
- **Persistence (`persistBox`)**: When enabled, final box positions and dimensions persist in the host page's localStorage (`xiaochun:box[:<namespace>]`). Position clamping ensures the container remains visible within the viewport upon window resize.
- **Selection Blue Box Prevention**: During gestures, host and iframe containers apply `user-select: none`, pointer capture on corners, and suppress default touch callouts to avoid triggering browser selection boxes.
- **Corner Handles Styling**: Corner handles and 3D guide rails share semi-transparent white geometry paired with an underlying soft shadow (`src/core/interaction/guideStyle.ts`), maintaining visibility against both dark and light host backgrounds without harsh borders.

### 2.9 Camera Tuning (`camera`)

Host applications can adjust camera framing using 4 specific parameters:

| Property | Valid Range | Default | Description |
| :-- | :-- | :-- | :-- |
| `fov` | 15 – 60° | 30 | Vertical field of view. Distance automatically compensates via `extent / (2 * tan(fov / 2))` to maintain perceived character scale. |
| `distance` | 1 – 15m | ≈ 2.50m | Distance from camera to character. Explicit settings bypass stored camera distance. |
| `height` | −1 – 1m | 0 | Vertical framing offset: positive values raise camera/target (lowering character in frame). |
| `intro` | boolean | true | Enables post-load cinematic camera push animation (~1.1s). |

- Parameter adjustments clamp to boundaries with `console.warn`. Horizontal azimuth rotation is locked forward (horizontal dragging maps to character `bodyTurn`).

## 3. Response Headers & Deployment Requirements

| Path | `X-Frame-Options` | `Content-Security-Policy` | `Permissions-Policy` | COOP / COEP / CORP |
| :-- | :-- | :-- | :-- | :-- |
| Main Site `/*` | `DENY` | — | `camera=(), microphone=(self), geolocation=(), interest-cohort=()` | `same-origin` / `credentialless` / — |
| `/embed`, `/embed/*` | **Removed** | `frame-ancestors <whitelist>` (default `*`) | Same as above (`microphone=(self)`, host must delegate) | `same-origin` (ignored in iframe) / `credentialless` / `cross-origin` |

Configuration checkpoints (must match):
1. **Worker / SSR**: `src/lib/securityHeaders.ts` evaluates `EMBED_FRAME_ANCESTORS` from `wrangler.jsonc`.
2. **Static Prerender**: `public/_headers` strips XFO via `! X-Frame-Options` and defines `Content-Security-Policy: frame-ancestors *`. Tightening the whitelist requires updating both locations.

Host requirements:
```html
<iframe src="https://xiaochun.firetable.tech/embed?host=https%3A%2F%2Fexample.com"
        allow="microphone; autoplay" loading="lazy"
        width="320" height="480"></iframe>
```

### 3.1 Optional: Cross-Origin Isolation for Multi-Threaded WASM

By default, `crossOriginIsolated === false` inside third-party iframes, restricting onnxruntime-web to single-threaded WASM. Enabling multi-threading requires:
1. Host page isolation headers: `Cross-Origin-Opener-Policy: same-origin` + `Cross-Origin-Embedder-Policy: credentialless` (or `require-corp`).
2. `/embed` headers: Sends `COEP: credentialless` + `CORP: cross-origin`.
3. Host iframe permissions: Set `createXiaochun({ crossOriginIsolated: true })` or pass `allow="cross-origin-isolated"`.

### 3.2 `/vrm/*` Cache Headers (`public/_headers`)

`/vrm/*` assets serve `Cache-Control: public, max-age=3600, must-revalidate`. Long immutable caching is avoided because model URLs omit content hashes; version invalidation relies on IndexedDB cache keys (`url + sha`).

### 4.3 `createXiaochun` Options Reference

```ts
createXiaochun({
  container: '#avatar',          // Target element or selector
  src: 'https://xiaochun.firetable.tech/embed',
  origin: undefined,             // Inferred from src by default
  allowedOrigins: [],            // Additional trusted origins
  lazy: true,                    // Idle + viewport mount; 'click' for on-demand
  lazyMargin: 200,               // Preload margin in px
  placeholder: '/xc.webp',       // Placeholder image URL
  transparent: false,            // Enable canvas transparency
  width: 600, height: 1080,      // Dimensions in px or CSS length
  position: 'inline',            // 'inline' | 'bottom-right' | 'bottom-left'
  draggable: false,              // Left-drag moves window
  resizable: false,              // Drag corners to scale
  borderRadius: undefined,       // Wrapper border-radius (default 20px non-transparent, 0 transparent)
  lang: undefined,               // 'zh-CN' | 'en' | 'ja'
  outfit: undefined,             // Initial outfit ID
```

## 5. Lighthouse & First-Screen Best Practices

1. **Placeholder + Lazy Mounting**: Render a static `<img>` during initial load; delay iframe creation until viewport entry and browser idle.
2. **Explicit Dimensions**: Provide fixed width/height values with `contain: layout style` to prevent Cumulative Layout Shift (CLS).
3. **Lazy Heavy Models**: Default `heavy="lazy"` avoids downloading multi-megabyte weights before user engagement.
4. **Visibility Pausing**: Suspend the render loop via `xc.pause` when offscreen to preserve GPU resources.
5. **Deferred Loading**: Use `defer` on script loaders to avoid blocking the document `load` event.

## 7. Risks & Known Constraints

| Risk / Constraint | Details & Mitigation |
| :-- | :-- |
| **Storage Partitioning & Asset Duplication** | Third-party iframes maintain partitioned IndexedDB and Cache Storage buckets per top-level domain. Users visiting separate host domains will download separate copies of model assets. Keep `heavy="lazy"` to minimize bandwidth. |
| **Cross-Origin Isolation & Threading** | Multi-threaded WASM requires top-level host COOP/COEP isolation and explicit `cross-origin-isolated` permissions. In un-isolated environments, ORT falls back to single-threaded execution. |
| **Microphone Access** | Requires HTTPS, host `allow="microphone"` delegation, and user permission per iframe origin. |
| **Autoplay Restrictions** | Audio playback requires prior user interaction on the host document and `allow="autoplay"` permission on the iframe. |
| **WebGL Context Limits** | Each iframe allocates an independent WebGL context (~16 limit on desktop Chrome). Keep instances to one per page and call `destroy()` upon unmounting. |
| **Clickjacking Defenses** | Defaults to `frame-ancestors *`. Production hosts are encouraged to restrict allowed parent domains via `EMBED_FRAME_ANCESTORS`. |
| **Scroll Wheel Capture** | In opaque scenes, scroll wheel events inside the iframe bounding box are captured as zoom operations. Set `controls="false"` if unobstructed page scrolling is required. |
